Lesson — Makefiles

Learning Outcome(s): LO3 — Use language tools (compiler, linker, build automation) to construct procedural programs.

Assessment alignment: Final Exam (Build process and dependencies).

What is a makefile?

A makefile is a text file that describes how a program is built from source files. It records:

  • Which source files belong to the project
  • How each source file is compiled
  • How object files are linked into an executable
  • Which files depend on which other files

The makefile is processed by a tool called make. On Windows with Microsoft tools, this utility is called nmake.

While IDEs (like Visual Studio) automate compiling and linking for you, makefiles expose what is actually happening under the hood and allow projects to be built consistently, repeatably, and efficiently.

The compile–link model (recap)

Building a C program happens in two conceptual phases:

  1. Compilation: each .c file is compiled into an object file (.obj on Windows, .o on Unix-like systems).
  2. Linking: all object files are combined into a single executable, and references to library functions (e.g., printf) are resolved.

In small projects this can be done manually, but as projects grow, tracking dependencies and rebuilding only what changed becomes difficult. This is the problem makefiles solve.

Example project

Consider a small statistics program composed of multiple source files:

  • stats.c — contains main
  • mathfuncs.c — implements math routines
  • display.c — handles output
  • mathfuncs.h — shared function prototypes

Each .c file is compiled separately, producing object files, and then all object files are linked together into one executable.

Importantly:

  • display.c depends on mathfuncs.h
  • mathfuncs.c depends on mathfuncs.h
  • stats.c depends on mathfuncs.h

If mathfuncs.h changes, all files that include it must be recompiled.

Basic makefile syntax

A makefile is composed of rules. Each rule has:

  • a target
  • a list of dependencies
  • a command to build the target
target: dependency1 dependency2
command to build target

Important: The command line must begin with a tab character, not spaces.

Example makefile

The following makefile expresses the dependencies for the statistics project. The compiler shown here (cl) is an example; the same structure applies to other compilers such as gcc.

statistics: display.obj mathfuncs.obj stats.obj
cl display.obj mathfuncs.obj stats.obj

display.obj: display.c mathfuncs.h
cl -c display.c

mathfuncs.obj: mathfuncs.c mathfuncs.h
cl -c mathfuncs.c

stats.obj: stats.c mathfuncs.h
cl -c stats.c

When nmake is run, it builds the first target by default. If a dependency is newer than its target, the rule is executed.

Incremental builds

One of the main advantages of makefiles is incremental compilation.

If only stats.c changes:

  • Only stats.obj is recompiled
  • The executable is relinked
  • Other object files are reused

This can significantly reduce build times in larger projects.

A specific target can also be built directly:

nmake stats.obj

Additional targets

Makefiles often include utility targets that are not part of the normal build. A common example is clean, which removes generated files.

clean:
del *.obj *.exe

This target is only executed when explicitly requested:

nmake clean

Macros (variables) in makefiles

Makefiles support macros (variables) to avoid repetition and make changes easier.

CC=cl
EX=obj

statistics: display.$(EX) mathfuncs.$(EX) stats.$(EX)
$(CC) -o statistics.exe display.$(EX) mathfuncs.$(EX) stats.$(EX)

display.$(EX): display.c mathfuncs.h
$(CC) -c display.c

By changing only the macro definitions, the same makefile structure can be reused with a different compiler or platform.

Key takeaways

  • Makefiles describe how a program is built and what depends on what.
  • They automate compiling and linking across multiple source files.
  • They enable incremental builds by tracking file timestamps.
  • They make builds reproducible and tool‑independent.
  • Understanding makefiles helps demystify what IDEs do automatically.
