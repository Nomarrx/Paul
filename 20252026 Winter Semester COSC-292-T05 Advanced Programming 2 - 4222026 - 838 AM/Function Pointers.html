Lesson — Function Pointers

Learning Outcome(s): LO5 — Use pointers to functions to implement callbacks and higher‑order operations.

Assessment alignment: Midterm 1 (Function pointers & callbacks).

What is a function pointer?

A function pointer stores the address of a function. Because functions live in memory like everything else, you can take their address & store it in a pointer.

Syntax

typedef returnType (*AliasName)(parameter list);

Where function pointers are used

  • Callbacks
  • Event handlers
  • Library hooks (qsort, signal handlers, etc.)
  • Object systems in C (function pointer “methods”)

Example — defining a function pointer type

typedef int (*FNPTR_TYPE)(int);

This means: FNPTR_TYPE is a pointer to a function taking int and returning int.

Functions matching the typedef

int doSquare(int x) { return x * x; }
int doAdd(int x)    { return x + x; }
int doNothing(int x){ return x;     }

Callback function: operate on each array item

#include <stdio.h>
#include "funcs.h" // typedef + prototype

void iterateNumbers(int iArray[], int iSize, FNPTR_TYPE myFunc)
{
    for (int i = 0; i < iSize; i++)
    {
        int val = myFunc(iArray[i]);
        printf("The value %d after the operation is %d\n", iArray[i], val);
    }
    printf("\n");
}

Calling with different function pointers

int iArray[] = {45, 56, 626262, 30, 2};
int iSize = sizeof(iArray)/sizeof(int);

iterateNumbers(iArray, iSize, doSquare);
iterateNumbers(iArray, iSize, doAdd);
iterateNumbers(iArray, iSize, doNothing);

Note: Function names decay to addresses, so &doSquare is unnecessary.

What if signatures don’t match?

Passing a function with the wrong signature compiles with a warning but produces undefined/unpredictable results.

Example mismatched signature

int dontMatchSignature(short x)
{
    return (int)x;
}

iterateNumbers(iArray, iSize, dontMatchSignature); // NOT safe

Values outside the range of short will wrap or truncate, demonstrating why matching signatures matters.

Summary

  • typedef removes messy pointer syntax from function pointers.
  • Function pointers allow higher‑order programming.
  • Matching signatures ensures safety.
  • Function names evaluate to their addresses automatically.
